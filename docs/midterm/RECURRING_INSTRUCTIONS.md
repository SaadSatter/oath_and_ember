# Recurring instructions across development sessions

This analysis answers one question: which instructions did the owner give **repeatedly during development**, and which were introduced **only when midterm work began**? The reusable skills (`game-rules-audit`, `session-evidence`) are built from the first group plus the official midterm guidelines (`docs/midterm/MIDTERM_GUIDELINES.md`). They must not present midterm-era requirements as long-standing practice.

## Method

- **Sources.** The owner's pasted briefs (Codex attachment files, and pasted briefs in Claude transcripts) and the owner's short chat instructions in the implementation sessions listed in `docs/agent-sessions/README.md`.
- **Not counted.** `AGENTS.md` is injected into every Codex session and imported by `CLAUDE.md`. It repeats server authority and the typecheck/test/build triad in *every* session automatically. That is configuration, so it is not counted as a repeated human instruction. Text written by agents is not counted either.
- **Cutoff.** 2026-10-22, the day the midterm architecture brief was pasted (`docs/agent-sessions/14-…`).
- **Matching.** One regular expression per theme, case-insensitive (listed below the table). Each match was spot-checked. Three false positives were found and the patterns tightened: "multiplayer-visible enemies" had matched *player-visible*, and "ordinary movement snapshots" (an animation rule) had matched *ordinary movement*, and an unrelated course document had passed the game filter because "remember" contains "ember". Briefs are now selected with word-boundary matches on Oath, Sieg, Coco, Ember and Emberbrook.
- **Reproduce.** Run `python3 -I scripts/evidence/extract_sessions.py --out /tmp/facts.json` and then `python3 -I scripts/evidence/recurring_instructions.py --facts /tmp/facts.json`. This needs the local transcripts, which are not committed.
- **Limits.** Keyword matching misses paraphrases, so the counts are lower bounds. Twelve of the briefs (2026-09-30 to 2026-10-08) survive only as Codex attachment files with no session transcript, see `docs/agent-sessions/00-pre-log-codex-briefs.md`. Owner chat in Codex sessions is mostly short feature or art requests, so most themes appear in briefs rather than chat.

## Reading the result

**Repeated before the midterm.** These became the core of `game-rules-audit` and `session-evidence`:

- **Server authority.** Clients submit intent; the server owns position, HP, damage, puzzles, skills and cooldowns.
- **Preserve rules and approved artwork.** Do not change rules to fit art or tooling.
- **Validate.** Run typecheck, tests and build, and report the actual result.
- **Approval gates.** Stop for the owner between phases.
- **No overclaiming.** Do not report anything unverified as done.
- **Evidence capture.** Screenshots, provenance and two-client checks. In chat this was "show a play through" four times in session 01 (2026-10-15 to 16), and on 2026-10-22: "Don't use screenshots, I need a recorded video of the game play in normal speed."
- **Two-client synchronization.**

**Occasional before the midterm.** Real mechanics instead of teleports appeared in one brief and in one chat instruction about cutscene movement (session 07). That was about player-facing behaviour, not evaluation. As an evaluation rule ("no fixtures as a substitute for play"), it dates from the midterm briefs.

**Introduced for the midterm.** The skills cite these to `MIDTERM_GUIDELINES.md` and the 2026-10-22+ briefs, not to earlier history:

- the information boundary and hidden-state leakage;
- the baseline, model player and evaluation suite;
- independent review.
