# Approved directional walking

The original `Images/Sprites/Walking Animation.png` is preserved as a source reference, outside runtime assets. `scripts/normalize_walk_references.py` uses explicit per-pose bounds and anatomical ground anchors rather than treating the decorated 1536×1024 sheet as a grid. It retains supplied colors and alpha, removes effectively invisible residual matte (alpha ≤10), discards neighboring connected fragments, and excludes reviewed neighbor wedges in overlapping Oath profiles. No art is regenerated or mirrored.

Each hero has 24 normalized walk PNGs: `walk_{down,up,right,left}_{01..06}.png` in its existing public character directory. All frames use transparent 48×64 cells and foot anchor (24,60). Common walk-reference reduction is 0.285, matching the original idle reference's approximately 50-pixel visible height. Anchors remain consistent across each row rather than aligning each frame's bounding-box bottom, preserving the authored stepping motion. Exact crop/anchor provenance is in `WALK_ASSET_PROVENANCE.json`; `normalized-walk-preview.png` provides visual QA.

The loaded `top-down.png` is a 1344×64 sheet with 28 cells: existing idles down/up/left/right at indices 0–3, then six-frame walks down/up/right/left at indices 4–9, 10–15, 16–21 and 22–27. `top-down-idles.png` remains an idle-only source for reproducible assembly and is no longer the loaded texture. Replace the combined sheet to change runtime art; individual PNG changes alone do not change it. The extraction scripts overwrite derived assets, so avoid rerunning them after installing final artwork.

Central definitions map down/up/right/left to existing gameplay-independent semantic states walk_south/north/east/west. All walk clips loop at 8 FPS using Phaser elapsed game time. Existing velocity selects locomotion, existing facing selects stationary idles, and PlayerView starts playback only when the resolved clip changes. Rendering cadence, network cadence, visual scale and canvas dimensions do not set animation speed. Attack/ability/hurt clips still fall back to approved directional idles, and platformer scenes retain geometric rendering. F4 remains available.

No server, protocol, shared physics, movement, collision, abilities or puzzle code changes are required. Per-hero scale and origin remain in `characterVisuals.ts`. Tests verify six-frame manifests, semantic selection, walking-to-idle transitions without per-frame restarts, and normalized RGBA dimensions. Existing responsive and multiplayer tests remain required.

Validation: `npm run typecheck`, `npm test` (30 passing tests), and `npm run build` passed. Initial sandboxed tests could not bind a local socket; the permitted rerun passed. Two browser clients in room 9RXFLE loaded the combined sheets, rendered both heroes, and moved independently using keyboard and touch input. A screenshot is saved as `walking-in-game.png`. Automated PlayerView verification confirms walking transitions and stable playback keys; this pass did not repeat the previous four-size visual sweep or physical-device testing.
