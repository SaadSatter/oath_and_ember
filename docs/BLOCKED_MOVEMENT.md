# Stable movement against barriers

Shared movement sweeps each requested axis to the nearest obstacle boundary, using the original displacement throughout the collision pass. The old loop zeroed velocity at the first obstacle, then used that zero velocity to choose a side at subsequent overlapping obstacles. This could push heroes across objects or make reconciliation jump. Stationary overlap no longer teleports the player; swept tests also prevent crossing thin obstacles during larger steps. Diagonal movement slides along a free axis. Top-down positions remain inside world bounds.

`Player.movementIntent` is clamped in shared movement and populated by the server from validated input. It is distinct from collision-resolved velocity. Animation selection uses this intent to continue directional walking in place against an obstacle, returning to idle on release. Actual position, velocity, HP and combat remain authoritative. Client prediction runs the identical collision code, and partners receive the same intent through snapshots. Scene transitions reset locomotion intent.

Verification: typecheck,94 tests and build. Collision tests cover overlapping obstacles in both orders, sustained contact, thin-wall sweeps, sliding, stationary overlap, walking/idle selection and exact prediction agreement. The real Socket.IO house integration test verifies identical blocked position and movement intent on both clients.

Authoritative placement fixtures establish obstacle contact, return to the door and approach the forest exit; keyboard input drives the actual checks. Source art, collision geometry and sprite scale are unchanged by this fix.
